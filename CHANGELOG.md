# Changelog

## Unreleased

### Security
- Docker image runs as the unprivileged user `fantoma` (uid 1000). `docker-entrypoint.sh` starts as root only to re-own the profiles volume and `/var/log/supervisor`, then drops to that user with `setpriv`; supervisord, Xvfb, x11vnc, websockify, the server and the browsers all run unprivileged. supervisord's socket and pidfile moved to `/tmp`.
- `.dockerignore` added: `.env`, `.git`, `.worktrees`, `.stage-runs`, logs and caches no longer end up in the image. Before this a `COPY . /app` shipped the build directory's `.env` inside the image.

### Changed
- Profiles volume path is `/home/fantoma/.local/share/fantoma` (was `/root/...`). Update the mount in your compose file; the entrypoint re-owns an existing volume on first start.

## 0.12.0 — 2026-11-05

### Upgrading from 0.11

The defaults are stricter. Read this before you deploy.

- **The HTTP server needs a key or loopback.** With `FANTOMA_API_KEY` unset the server only binds to `127.0.0.1`, refuses any client that is not loopback (503), refuses any browser `Origin` or non-loopback `Host` header (403), and refuses requests that arrive through a proxy (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `Via`). The Docker image listens on all interfaces, so the container exits at start unless `FANTOMA_API_KEY` is set (or `FANTOMA_INSECURE_NO_AUTH=1`, on purpose). Send the key as `X-API-Key` or `Authorization: Bearer`. `/health` is always open.
- **noVNC in the container needs `FANTOMA_VNC_PASSWORD`**, or `FANTOMA_VNC_ALLOW_NO_PASSWORD=1`; otherwise the VNC server does not start.
- **Every `POST`, `PUT`, `PATCH` and `DELETE` must send `Content-Type: application/json`** (a JSON body, `{}` for `/stop`). A bare `curl -d` or `requests.post(url)` with no `json=` now gets `415`.
- **Private and internal targets are refused** by the server (and by `DomainPolicy(block_private=True)`): RFC 1918, CGNAT, loopback, link-local, cloud metadata, and `.lan`, `.home`, `.home.arpa` names, after DNS resolution. Set `FANTOMA_ALLOW_PRIVATE=1` to drive an intranet.
- **Request proxies** must be `http`, `https`, `socks5` or `socks5h` on a public host; a proxy on a private address is refused unless `FANTOMA_ALLOW_PRIVATE=1`.
- **MCP over HTTP off loopback needs `FANTOMA_MCP_TOKEN`** (or `FANTOMA_MCP_INSECURE=1`).
- **Strict domain mode (the default under a policy):** cross-origin subresource redirects fail, including http to https and CDN hops (use the final URL); `POST` navigations answered with 307/308 are refused; URLs with a backslash or control character are refused; an SSO login that redirects to another host will not have the password typed; service workers are off; a page that reassigns `window.WebSocket` breaks. Code driving `page.goto` itself must call `fantoma.browser.domains.settle_hops(page)` afterwards.
- `history.json` and `fantoma.log` are written `0600`. Benchmark Telegram settings moved to `FANTOMA_BENCH_TELEGRAM_TOKEN` and `FANTOMA_BENCH_TELEGRAM_CHAT`.
- Known limits are listed in the README (Limitations): the Chromium service worker lock is JS-level hardening; Camoufox strict mode may leave a redirect inside an iframe on the hop page; a sandboxed iframe without `allow-scripts` is not guarded; the Docker image still runs as root.

### Added

- **Prompt order for cache reuse.** The navigator system prompt is now fixed text (rules and action list), byte-identical on every step and every subtask; it no longer carries the subtask or done condition. The user message runs: subtask, done condition and date, then per-step notes (nudge, usable secrets, change line), then the WebMCP tool block when there is one, then the page last. Same content as before, reordered, so a server that caches prompt prefixes (llama.cpp, vLLM, hosted APIs) reuses the whole fixed part on each step. Measured on a local llama.cpp server with a 5-step login-and-add-to-cart task: cached prompt tokens on navigator steps rose from about 510 to about 960 per request. The replan prompt keeps the decompose system text fixed and moves the failure notes into the user message. Design after browser-use's prompt layout (MIT, `browser_use/agent/prompts.py`); independent implementation. Tests: `tests/test_prompt_order.py`.
- **Today's date in prompts.** The navigator, planner (decompose, replan, summarise), extract and validator prompts now say `Today is <weekday> <YYYY-MM-DD>.` right after the task text, so "next Friday" resolves to a real date. It sits in the user message, not the fixed prefix, so the prefix stays identical across days too.
- `FANTOMA_LLM_SLOT_HINT=<n>` (off by default, self-hosted endpoints only) sends `id_slot` so a llama.cpp server keeps a run's prompt cache in one slot. Accepted and honoured through a proxy in testing, but the server's own slot choice already found the prefix, so it gave no measurable gain; leave it unset unless your server picks slots badly.

- **Stable element numbers.** `[12]` now follows the element it was given to instead of its position in a list rebuilt on every read. Each listed element stores role, accessible name, its index among elements with the same role and name, how many such elements there were, and its link target or item label when known (new module `fantoma/dom/refs.py`). A control still on the page keeps its number across reads in a task, a new control gets a new number, and a gone control's number is never reused. The prompt format and the small numbers are unchanged.
- Acting on `[N]` resolves by identity against the live page: the original (same role, name, position) if the number of look-alikes is unchanged; else role and name if exactly one control matches; else the action fails with `element [N] is gone, re-read the page` (or `now matches several identical elements, re-read the page`) in the result notes. It never guesses. A number from another page (different origin or path) is refused. Design after agent-browser's element resolution (Apache-2.0, `cli/src/native/element.rs`: stored id first, role and name fallback, refuse when ambiguous); independent Python implementation, no code copied. Chromium's `aria_snapshot(mode="ai")` refs reset on every read, so they are not used.
- Queued actions are no longer dropped wholesale when the page structure changes. Each one is kept if its target still resolves to exactly one element and dropped if not; the log says which (`keeping N ... dropping M: click[7] (gone or ambiguous)`). If the URL itself changed, everything queued for the old page is still dropped. Actions with no element target are kept. Tests: `tests/test_stable_refs.py`; live check `tools/stable_refs_live.py`.

- **One page read per step.** The navigator arms a step snapshot (`fantoma/dom/page_reads.py`, `AccessibilityExtractor.begin_step()`) so the before/after diff, the element list, the content summary and the state tracker share one ARIA read. It is dropped by `invalidate()` before and after every action, and silently when the page URL changes. Outside a navigator step nothing is cached. Per step: 3 to 5 ARIA reads down to 2 (one at the start, one after the action). The per-element occlusion check is now one `page.evaluate` for the whole element list (about 20 evaluates down to 1).
- Every read in the step loop (ARIA snapshot, scroll info, JSON-LD, occlusion, blocker check) is bounded: default 15 s, `FANTOMA_READ_TIMEOUT` to change. A read that does not answer returns the usual degraded result with a warning in the log, and the rest of that step's reads skip straight to degraded instead of waiting again. The timer needs the main thread; in other threads only Playwright's own `aria_snapshot` timeout applies.
- Each navigator step logs `step N: reads=X evals=Y secs=Z prompt_chars=W`. `tools/read_cost_bench.py` measures the read path per step without a model.
- Optional blocking of fonts and media: `Fantoma(block_resources=True)` / `FANTOMA_BLOCK_RESOURCES=1`, off by default. Blocks only resource types `font` and `media` and URLs ending .woff .woff2 .ttf .otf .mp4 .webm .mp3 .m4a .ogg; never images, stylesheets, scripts or xhr/fetch. Runs before the domain policy and hands everything it does not block on, so the policy still applies. Skipped with one warning when attached to your own Chrome. The count is `engine.blocked_requests` and is logged at stop. Patterns borrowed from Crawlee for Python's `BlockRequestsFunction` (Apache-2.0). New module `fantoma/browser/blocking.py`.
- **Secrets tied to their site.** `sensitive_data` now also takes `{"https://*.example.com": {"password": "..."}}`. A scoped value is typed only if the page URL, read again right before the fill, matches the pattern; otherwise the action fails with "secret 'name' is not allowed on this site" and nothing is typed. The flat format is unchanged. Invalid patterns raise `ValueError` when the `Agent` is built. The matcher is in `fantoma/secrets_scope.py` (design after browser-use's `match_url_with_domain_pattern`, MIT).
- Placeholders scoped to other sites are not listed to the model, and their real values are masked out of page text, planner summaries, extracted answers and the returned result.
- Fast-path `login()` re-checks the page URL before each fill (username and password separately). `POST /run` answers a bad `sensitive_data` pattern with a clean 400 and no secret values in the text.
- `tools/secrets_scope_live.py`: local two-site check, no model.
- Attach to a Chrome you already run: `Fantoma(cdp_url=...)`, `Agent(cdp_url=...)`, `cdp_url="auto"` (reads `DevToolsActivePort`, falls back to port 9222), CLI `--cdp-url` on `read` and `run`, env `FANTOMA_CDP_URL`. Chromium only (Camoufox raises `ValueError`). Fantoma works in its own tab, hides your tabs from the model, and on stop closes only the tabs it opened without closing the browser. Loopback hosts only unless `allow_remote_cdp=True`. Live check: `tools/cdp_attach_live.py`.
- `BrowserEngine.supports_aria_refs()` and `supports_webmcp()` report whether the live page object offers `aria_snapshot(mode="ai")` with `get_by_ref`, and a `webmcp` API. True on Chromium with Patchright 1.64.3, false on Camoufox. `supports_webmcp()` checks the client API only; WebMCP is not enabled yet.
- Chromium option `chromium_full_headless` (env `FANTOMA_CHROMIUM_FULL_HEADLESS=1`), off by default. Headless runs use the full Chrome build instead of chrome-headless-shell, which lacks features such as WebMCP.
- **Agent Skills file.** `skills/fantoma/SKILL.md` tells a coding agent when and how to use Fantoma. It ships inside the package; `fantoma skill` prints it and `fantoma skill --install DIR` copies it to `DIR/fantoma/SKILL.md` (`--force` to overwrite).

- WebMCP support, off by default: `Fantoma(webmcp=True)` / `FANTOMA_WEBMCP=1` (Chromium only; ignored with a warning on Camoufox). Launches full Chrome with `--enable-features=WebMCP`, lists a page's registered tools in the step prompt, and adds a `WEBMCP name {json}` action. `Fantoma.webmcp_tools()` and `Fantoma.webmcp_call(name, args)` expose it directly. Tool text is treated as untrusted (name check, sanitising, caps, injection scan, fencing) and calls with `<secret:...>` placeholders in the arguments are refused. Tools the page marks consequential or not read-only are hidden and refused unless `webmcp="all"` / `FANTOMA_WEBMCP=all`; `untrustedContent` results get a warning. New module `fantoma/webmcp.py`, live check `tools/webmcp_live.py`.

### Security

- **Names are resolved under `block_private`.** `127.0.0.1.nip.io`, `localtest.me` and rebinding names looked public to the textual check and reached the local network and cloud metadata. With `block_private` on (the HTTP server's default), `DomainPolicy.permits()`, `/start`, `/navigate`, `/read`, `/run` and `/login` now resolve the name (3 s timeout, cached 60 s per policy) and refuse it if any address is private, CGNAT included, or if the lookup fails. Policies without `block_private` never resolve. Limit: the browser does its own lookup afterwards, so a rebinding answer that changes between the two lookups can still get through; closing that needs a proxy that pins our resolution and is out of scope.
- **Every redirect hop is checked, and the browser never follows a 3xx itself.** In strict mode only the first `Location` was checked; Chromium and Camoufox followed later hops without running the handler. The first fix verified the chain with `route.fetch` and then handed the browser a 302 to the verified end, but the browser's own request to that URL is never routed, so a server that answered the checker 200 and the browser 302 to a refused host got through (confirmed in a real browser for GET and for POST 303 and 307). Now a page or frame navigation answered with a permitted redirect gets a small `200` page (`no-store`, `default-src 'none'` CSP, nonce-only inline script, `data-fantoma-hop`) that runs `location.replace` to the Location. That is a new navigation, so it comes back through the route handler and is checked again, hop by hop, and the address ends up right. Subresources (images, scripts, fetch, XHR) are walked by the handler with redirects off, every hop checked, and the final response is returned in place of the first, but only while every hop stays on the first URL's origin (see the fifth-audit lines below: a cross-origin hop is refused); the browser is never handed a 3xx. Up to 10 redirects are allowed; the 11th aborts. A `Location` that is not http or https is refused. Cookies and credentials are not forwarded to followed hops. The probe-ahead (HEAD) logic is gone. Chains behind a POST: see the third-audit lines below.
- **Callers of `page.goto` under a policy.** `goto` now resolves on the hop page for a redirecting URL. Fantoma's own navigation (`engine.navigate`, new tabs, `wait_for_dom_stable`) waits for the end of the chain through `fantoma.browser.domains.settle_hops(page)`; code that drives the page directly should call it after `goto`. The real final status is kept in `DomainPolicy.nav_status`.
- **Cross-origin subresource redirects are refused in strict mode.** The handler walked a redirect chain and returned the last answer in place of the first, so a page on one origin could read, with the context's cookies, a body from another origin through a redirect (CORS bypassed), and the far side's `Set-Cookie` landed on the first host. If any hop of a subresource chain differs from the original request in scheme, host or port, the request is aborted with a log line. Same-origin chains still work, and `Set-Cookie` is stripped from what is handed back (the cookie jar has already applied it). Navigations are unchanged: they cross origins through hop pages. A subresource that redirects http to https (or to another host) now fails under a strict policy; use the final URL.
- **One URL check for every fetch.** Python and a browser read `http://127.0.0.2:80\@localhost:80/` differently (host `localhost` to `urlparse`, `127.0.0.2` to a browser, which reads a backslash as a slash), so an allowed-looking Location could reach a refused host. `fantoma.browser.domains.parse_url` now refuses, for http, https, ws, wss and ftp, any URL with a tab, CR or LF, a backslash or whitespace or control character in the authority, or a host or port that changes when backslashes are read as slashes. `DomainPolicy.permits` (and so the HTTP server's URL check) and every redirect `Location` go through it; a Location holding a backslash or control character is refused outright.
- **Service workers are blocked** (`service_workers="block"`) on every context Fantoma creates, Camoufox and Chromium, persistent or not. A worker's `fetch` was not routed, so it could reach a refused host. Checked in both browsers: without the option a worker fetched a loopback address, with it `register` does nothing. A context Fantoma attaches to over `cdp_url` is the user's own and keeps its settings, so service workers there are not blocked by Fantoma; only the tabs it opens are policed.
- **Service worker block closed for real.** `service_workers="block"` only shadows `navigator.serviceWorker.register`; `ServiceWorkerContainer.prototype.register.call(navigator.serviceWorker, '/sw.js')`, deleting the instance property, or doing the same from an iframe's realm registered a worker whose fetches were not routed, and it reached a refused host in both browsers. Camoufox now launches with `dom.serviceWorkers.enabled=false` (merged into the existing prefs, persistent or not). Every context Fantoma creates, both browsers, also gets an init script that locks `ServiceWorkerContainer.prototype.register` and the instance property (non-writable, non-configurable, rejects with `SecurityError`). The Chromium lock is JS-level hardening, not an engine switch. A context attached over `cdp_url` is not covered. Real-browser tests: `tests/test_audit_fixh.py`.
- A page that fakes a hop page with `pushState` stalls `settle_hops` once: the URL is dropped from the policy's hop set when the wait times out.
- Strict mode: if a response comes back in an encoding Playwright cannot decode (anything but gzip, deflate, br, identity), the fetch is retried once with `accept-encoding: identity` and logged; if it is still undecodable the request is aborted with a log line instead of handing the browser compressed bytes.
- Known limits: in Camoufox strict mode a redirect inside an iframe may stay on the hop page; the Chromium service worker lock is JS-level; a sandboxed iframe without `allow-scripts` cannot run the hop script (already listed above).
- **Redirect loops through hop pages stop.** More than 10 consecutive hop pages in one frame (an A to B to A loop ran thousands of requests in Chromium) are refused with a log line. A real answer ends the run.
- **Hop pages send no Referer** (`referrer` meta and `Referrer-Policy: no-referrer`), so the target no longer sees the URL that redirected, and the original `#fragment` is carried across when the Location has none.
- **A page cannot fake a hop page.** Fantoma only waits on a `data-fantoma-hop` page whose URL its own policy served as a hop page and has not served as a real answer since. The wait is capped at 5 s (was 15 s) and `wait_for_dom_stable` returns False, not a truthy value, while a real hop page is still showing.
- `DomainPolicy.nav_status` is keyed by URL without the fragment (use `DomainPolicy.status_for(url)`); it stays per policy, not per tab.
- Known limit: a sandboxed iframe without `allow-scripts` cannot run the hop script, so a redirecting URL loaded in it stays on the hop page.
- The carrier-grade NAT range 100.64.0.0/10 and the names `.lan`, `.home` and `.home.arpa` count as private in the domain policy, from one helper shared with the LLM client (`fantoma/netutil.py`).
- The keyless-remote refusal and `FANTOMA_BLOCK_PRIVATE` now apply under gunicorn and `flask run`, not only `python server.py`: the browser-side block is set when `server.py` is imported, and without `FANTOMA_API_KEY` a client that is not on loopback gets 503 (unless `FANTOMA_INSECURE_NO_AUTH=1`). `/health` stays open.
- `/run` checks a request `proxy`: http, https or socks5 only, and not a private or loopback host unless `FANTOMA_ALLOW_PRIVATE=1`.
- **Redirect chains behind a POST are checked.** Only the first `Location` of a POST was checked and the raw 3xx handed back, so POST 302/303 to a public page to `169.254.169.254` was never looked at. A POST answered 301, 302 or 303 is now followed with GET from the first `Location` on (what the browser does), every hop is checked, and the browser gets one 302 to the verified end. A POST answered 307 or 308 on a page navigation is refused (aborted with a log line), because a follow-up page cannot replay the body. For a subresource the handler replays a 307 or 308 with the original body, and only on the same origin (every cross-origin subresource redirect is now refused, not just POST replays). The HEAD probe from the earlier fix is gone, since it could be answered differently from the real request.
- **The keyless loopback server refuses cross-site requests.** Any web page could POST `text/plain` with `no-cors` to `http://127.0.0.1:7860/run` and the body was parsed as JSON. Bodies must now be `application/json` (415 otherwise; `force=True` is gone everywhere), and with no `FANTOMA_API_KEY` any request that carries an `Origin` header, or a `Sec-Fetch-Site` other than `none` or `same-origin`, gets 403. `/health` is exempt. With a key set the Origin rule does not apply.
- **The keyless guard is no longer blind behind a reverse proxy on the same host.** Without a key, a request carrying `X-Forwarded-For`, `Forwarded`, `X-Real-IP` or `Via` gets 503, because a local proxy makes every remote client look like loopback. A key is mandatory behind any proxy. `FANTOMA_INSECURE_NO_AUTH=1` skips this check only.
- **WebSocket guard honours `block_private`.** It ignored the private-host rule and was only injected when allow or block lists were set. It is now injected whenever `block_private` is on and refuses IP literals (the browser has already normalised `127.1`, `0x7f000001` and decimal forms), IPv6 including mapped and NAT64 forms, `localhost`, the local suffixes and the metadata names. A public-looking name that resolves to a private address cannot be caught in page JavaScript; the request-level check covers HTTP, not WebSockets. The guard is textual only (documented in the module docstring and README).
- A request `proxy` is rebuilt from its parsed parts and handed to the browser as `server` plus `username` and `password`. A netloc with a second `@`, or any comma, semicolon or whitespace, is refused, because the parser and the browser could disagree about the host.
- CLI `history.json` and `fantoma.log` are created owner-only (0600), and tightened if they already exist.
- MCP over HTTP: a non-loopback `FANTOMA_MCP_HOST` is refused unless `FANTOMA_MCP_TOKEN` is set (every request then needs `Authorization: Bearer <token>`) or `FANTOMA_MCP_INSECURE=1`. The HTTP transport also failed to start before (`FastMCP.run` takes no host or port); it now runs through uvicorn.
- Benchmark scripts no longer read a bot token from a personal config file; notifications use `FANTOMA_BENCH_TELEGRAM_TOKEN` and `FANTOMA_BENCH_TELEGRAM_CHAT` and are skipped when unset.
- **Non-network schemes are always refused.** `file:`, `chrome:`, `view-source:`, `resource:`, `javascript:` and `about:` other than `about:blank` are refused by `DomainPolicy.permits()` with or without a policy. `data:`, `blob:` and `about:blank` still pass.
- **The HTTP server refuses private hosts by default.** `/start`, `/navigate`, `/read`, `/run`, `/login` and `/manual/open` reject loopback, private, link-local and cloud metadata URLs, and the browser's own requests and redirects are blocked too (`FANTOMA_BLOCK_PRIVATE`, set by the server). `FANTOMA_ALLOW_PRIVATE=1` lifts it. Direct Python use is unchanged apart from the scheme rule.
- `/run` and `/start` accept a validated `allowed_domains` list.
- **Private-host check covers shorthand forms.** `127.1`, `0x7f000001`, `0177.0.0.1`, IPv4-mapped IPv6, `metadata.google.internal` and `*.internal` are now caught.
- **`/login` cannot type the password on another site.** Credentials are scoped to the login URL's host and the live page URL is checked before each fill, so a redirect mid-login gets nothing. Error text is masked.
- **The server will not start on a non-loopback address without `FANTOMA_API_KEY`** unless `FANTOMA_INSECURE_NO_AUTH=1`. The compose file publishes 7860 and 6080 on 127.0.0.1 only. x11vnc will not start without `FANTOMA_VNC_PASSWORD` unless `FANTOMA_VNC_ALLOW_NO_PASSWORD=1`.
- `/run` rejects `max_steps` outside 1 to 500 and `timeout` outside 1 to 3600 with a 400. A 500 returns a generic message and a log id; the masked error is in the log.
- Dependency floors raised: `mcp>=1.30.0` (fixes five high advisories in 1.26.0) and `werkzeug>=3.1.9`.
- The Dockerfile no longer hides a failed `pip install`.

- **WebSocket guard cannot be bypassed through the prototype.** `Guarded.prototype = Native.prototype` left `WebSocket.prototype.constructor` as the native constructor, so `new (WebSocket.prototype.constructor)(url)` skipped the check. The prototype's `constructor` now points at the guard, and `window.WebSocket` is defined non-writable and non-configurable so a page cannot reassign or delete it to get the native one back. Firefox-based browsers (Camoufox) also hand a script a blank same-origin iframe before the init script has run in it; `iframe.contentWindow` and `contentDocument` are now patched to guard that window on first access. Still open: `window[0]` and `window.frames[0]` reached in that first instant, and WebSockets from workers. Tests in Chromium and Camoufox.
- **GET and HEAD follow-up hops no longer carry the POST body.** Playwright reuses the original request's body (labelled `application/octet-stream`) when `post_data` is left out, so credentials posted to a 302 reached the next URL. Every hop whose method differs from the original now passes `post_data=b""` (confirmed with a local server logging Content-Length and body) and drops content-type, content-length, transfer-encoding and origin.
- **The keyless server refuses a foreign Host header (DNS rebinding).** A page on `attacker.example` whose name later resolves to 127.0.0.1 is same-origin to the browser, so it sent no Origin and no cross-site Sec-Fetch-Site. With no `FANTOMA_API_KEY`, any request whose Host (port removed) is not `localhost`, `127.0.0.1` or `[::1]` now gets 403. `/health` is exempt and not Host-checked. Not applied when a key is set, nor under `FANTOMA_INSECURE_NO_AUTH=1` (an operator who chose an open API on a non-loopback address). The container binds 0.0.0.0 and refuses to start without a key, so it is unaffected.
- **Every POST needs `Content-Type: application/json`, empty or not.** The 415 gate used to skip requests with no body, so a cross-site form POST to `/stop` or `/stop-benchmark` got through. Clients that send an empty POST must add the header (`httpx`'s `json={}` does; Fantoma's own MCP backend and tools already do).
- The DNS lookup pool is 16 workers (was 4), and lookups for the same host that are in flight together share one future, so one slow name asked for many times uses one worker.

### Changed

- Element numbers in `_last_interactive` are stamped as `el["index"]` and are no longer list positions. Code that addressed elements by list position should use `el["index"]` (`tools/live_read_check.py` and the fast path do). `AccessibilityExtractor.reset_refs()` starts a new numbering; the navigator calls it when a task starts.
- The `chromium` extra pins Patchright to `>=1.64.3,<1.65`. Camoufox and Playwright 1.58 are unchanged and import alongside it in one environment.
- Listed for the official MCP Registry: `server.json` and the `mcp-name` line in the README. The headline now says small local models can drive the read path, matching what the measurements show.
- Added `llms.txt`.

### Security

- Element numbers no longer match look-alikes: when the exact role and name finds nothing, the fallback accepts only a name equal after case and whitespace folding, so "Delete" no longer clicks "Undo delete".
- Element numbers for repeated controls (several "Remove" buttons) are checked against their link target and item label before use, so a same-length reorder of rows can no longer land on the wrong row; if nothing matches uniquely the action is refused. A control with neither link target nor label is still found by position only.
- The WebMCP prompt block is masked with the scoped secret store for the current URL; it crashed on `sensitive_data=None` and on the scoped form.
- The field-labelling prompt in form login fences page attribute values as untrusted and cuts each to 40 characters.
- Injection warning excerpts are cut from the same invisible-character-stripped text the match offsets come from.
- The resource blocker aborts a request when handing it on fails, instead of continuing it past the domain policy.
- The action cache directory is created mode 0700 and the setup config file is created 0600 from the first write.
- `fantoma` CLI no longer builds shell strings for `/monitor` and `/clear`.
- Hidden-text removal in `read` also drops text with a sub-pixel font size and absolutely positioned text whose box is fully outside the document.
- The dropdown popup selector built from the page's `aria-controls` is quoted as a CSS string.

### Fixed

- **MCP over HTTP answered 421 to everything off loopback.** `FastMCP("fantoma")` switches DNS-rebinding protection on with a loopback-only Host list at construction, and changing the host later did not widen it. With a non-loopback `FANTOMA_MCP_HOST` the Host list is now rebuilt from the bind address plus `FANTOMA_MCP_ALLOWED_HOSTS` (comma-separated names). Bound to `0.0.0.0` with a token and no names, the Host check is off and the bearer token is the guard.
- The MCP bearer scheme is matched case-insensitively (`bearer` works).
- **Server errors.** Only the new `BadRequestBody` (raised by `_json_object()` and the field accessors) and malformed JSON answer 400. A `KeyError`, `TypeError` or `ValueError` from the library is now a generic 500 with a log id instead of a 400 that echoed key names, and it is logged through `_masked`. HTTP errors such as 404 and 415 come back as JSON.
- `allowed_domains` cleaning no longer resolves names (a hundred entries at 3 s each outlasted the 75 s `/start` watchdog). Literal and suffix private checks stay; `permits()` resolves per request.
- DNS lookups run on a shared pool of 4 threads instead of one new daemon thread per timed-out lookup. When all four are stuck a new lookup is refused and the policy fails closed.
- The redirect limit was off by one: a chain of exactly 10 redirects ending in a 200 was aborted. 10 pass, 11 abort.
- `/login` no longer pretends to check a request proxy; it never used one. The check and its test are gone.

- `fantoma.__version__` and `server.json` said 0.11.3; both now match `pyproject.toml` (0.12.0), and a test keeps them in step.
- The HTTP server answers a missing JSON field or a wrong-shaped body with a 400, and any other unexpected error with the generic JSON 500, on every endpoint (`/press_key`, `/select`, `/scroll` and others returned Flask's HTML 500).

- A timed-out page read no longer makes every later read fail. The "page not answering" flag now expires after 5 seconds and is cleared at the start of each public call (`navigate`, `read`, `extract`, `login`, `Agent.run`), so one timeout cannot poison later calls in the same thread or server process.

- **Fantoma no longer kills other programs' browsers.** Clearing a wedged driver ran `pkill -f playwright/driver/node` (and the same for `camoufox-bin` and the glxtest Xvfb), which matched every Playwright browser on the machine, including a second Fantoma. Only processes started by this Fantoma are touched now. The Docker image sets `FANTOMA_REAP_ALL=1` to keep the old container-wide clean-up, since every browser there is Fantoma's.
- **A page that has arrived is read even when a script stalls.** A script at the end of a page that never finishes loading used to time out the navigation, and the retry in a new tab timed out the same way. When the page already has text on screen, Fantoma now reads it. A page with nothing drawn yet still fails as before.
- The live check reads its table page from scrapethissite.com. the-internet.herokuapp.com now holds scripts in the page head back for 30 seconds, so no browser could draw that page in time.

## 0.11.2 — 2026-10-08

### Security

- **The HTTP server listens on 127.0.0.1 unless a key is set.** With no `FANTOMA_API_KEY` it bound to every interface, so anyone on the network could drive the browser. `FANTOMA_HOST` overrides the choice. The Docker image sets it to `0.0.0.0`, because loopback inside a container cannot be reached from the published port.
- **A proxy named in a request body is ignored without a key.** It routed all browser traffic, logins included, through a host the caller picked. Set `FANTOMA_API_KEY` or `FANTOMA_ALLOW_REQUEST_PROXY=1` to allow it.
- **Profile paths stay under one directory** (`FANTOMA_PROFILE_BASE`, default `~/.local/share/fantoma`). `/start` and `/manual/open` accepted any path.
- **A requested timeout is capped at an hour**, so one call cannot hold the single worker indefinitely.
- **Domain policy covers schemes and private addresses.** With a policy active, `file:`, `chrome:` and `view-source:` are refused, and localhost, private, link-local and cloud metadata addresses are refused unless named in the allow list.
- Saved sessions and the form memory database are written owner-only (0600 files, 0700 folders). A warning is logged when sessions are saved as plain JSON because `cryptography` is missing.
- The weekly monitor runs its sender command without a shell.
- MCP over HTTP logs a warning when bound beyond loopback, since it has no authentication.

### Fixed

- **Dialogs are reported.** A confirm box was cancelled silently while the click reported success. Dialogs are now answered by `FANTOMA_DIALOGS` (`dismiss` by default, or `accept`) and the action result says what the dialog asked.
- **Tabs the site opens are reported**, with a hint to use `switch_tab`.
- **A crashed or closed tab is reported** instead of hanging the next read until the task timeout. Page reads now time out after 20 seconds.
- **HTTP errors are reported.** A 404 or 500 page adds an error to the state.
- **Clickable divs work.** Enter does nothing on a `div` with an `onclick` handler. Non-native elements get the key first and a synthetic click if the page did not react.
- **Pages whose controls sit only in an iframe** (card forms, embedded logins, `srcdoc` consent widgets) listed nothing to click.
- Calling Fantoma from a second thread raises a clear error instead of hanging later calls.

### Performance

- `humanize=False` now reaches the browser. Every click carried a 1 to 3 second pause regardless.
- Fixed sleeps after start, navigate, back and new tab are replaced by a wait for the page to settle.
- Change tracking on pages with thousands of identically named links is linear instead of quadratic.

## 0.10.0 — 2026-09-24

### Added

- **Read any page as clean Markdown, no LLM.** `fantoma read URL` on the command line, `Fantoma.read()`, `POST /read` and the `fantoma_read` MCP tool return the page as Markdown (headings, nested lists, tables, code blocks, quotes, links, open shadow DOM, a dropdown's current choice) plus every link on it, absolute and de-duplicated. `main_only` (default on) drops navigation, header, footer, aside and cookie banners; `selector` narrows to one element; `max_chars` cuts on a paragraph boundary.
- **The MCP server runs its own browser.** With `FANTOMA_MCP_BACKENDS` unset, `fantoma-mcp` drives a browser in-process, so an MCP client needs one command and no Docker. `FANTOMA_LLM_URL`, `FANTOMA_LLM_MODEL` and `FANTOMA_LLM_API_KEY` configure the model for `fantoma_run` and `fantoma_extract`; `fantoma_read` and `fantoma_login` need none. In this mode read, extract and login share one session, so a login carries over. Setting `FANTOMA_MCP_BACKENDS` keeps the Docker backends as before.
- **Prompt-injection defences** (`fantoma/safety.py`). Text a person cannot see never reaches a model (`display:none`, `visibility:hidden`, `opacity:0`, `aria-hidden`, `[hidden]`, zero font size, clipped or far off-screen boxes, zero-width and bidi characters). Page text sent to the navigator, planner, answer extraction and `extract()` is fenced in `<untrusted_web_content>` with a random id the page cannot forge, and each system prompt says fenced text is data. `read()` returns `injection_warnings`: excerpts that read like instructions aimed at an AI.
- **Allowed and blocked domains**, enforced by the browser on every request, not only navigation: `Fantoma(allowed_domains=[...], blocked_domains=[...])` or `FANTOMA_ALLOWED_DOMAINS` / `FANTOMA_BLOCKED_DOMAINS`. A page that talks the agent into loading a URL on another host sends nothing.
- **Block-page detection.** `read()` reports `blocked` as `bot_challenge`, `captcha`, `rate_limited`, `access_denied`, `http_error`, `login_wall` or `empty` instead of returning an interstitial as if it were the page.
- **JSON Schema extraction.** `extract()` and `fantoma_extract` accept a real JSON Schema; an object schema returns an object. The older flat `{field: type}` map still returns a list.

### Fixed

- **Found in review before release, and fixed:** the domain policy was bypassed by a redirect from an allowed host and by WebSockets, and ignored Unicode host names; nested web components repeated their text 2^depth times and leaked unslotted text; a failed page walk fell back to raw text that includes hidden text; `selector` pointing at a nav or footer returned nothing, and a bad selector silently returned the whole page; accordion headings built from buttons vanished; SVG icon titles and styles leaked into text; zero-size positioned wrappers hid their visible children; scroll-revealed content was missed (read() now scrolls first); normal short pages were flagged as blocked ("$1,429" read as a 429, "Reference #…" as access denied, the "protected by reCAPTCHA" notice as a captcha, "500 Startups" as an HTTP error); JSON replies with a list inside an object were parsed as the list; a custom dropdown could pick a same-named option from an unrelated native select; an MCP setup relying on the old default backend address silently switched to the built-in browser (it now uses a backend that answers there).
- **`pip install "fantoma[mcp]"` installed an MCP SDK the server could not import.** MCP 2.x renamed `FastMCP`; the extra is now pinned below 2.
- **Native dropdowns never worked for an agent (0/3 on the dropdown flow).** Small models click the `<option>` they want, which does nothing inside a closed native `<select>` in Firefox. Such a click now performs the select. `select()` matches label, then value, then case-insensitively, and opens scripted ARIA dropdowns. A dropdown now shows its current choice, its options are listed directly beneath it, and `[selected]` is no longer lost when an option is also `[disabled]`.
- **A successful select was reported to the model as "No visible changes".** The change line compared only the first state flag and never tracked `[selected]`, and repeated or unnamed controls shared one key, so a change to the second of two checkboxes was invisible too.
- **Controls behind a modal were offered to the model, and the filter meant to hide them never ran.** Its script was called with two arguments where Playwright passes one, so it raised on every element and kept everything. It had also been applied after the list was numbered, which would have shifted every later element one slot. It now runs before numbering, and hides a control only when an overlay (a fixed or sticky layer, or a modal dialog) sits on top of it, so a label drawn over a styled checkbox no longer counts as covering it.
- **Unnamed controls could resolve to a named one.** A bare checkbox was looked up among every checkbox on the page, so with "Agree to terms" and two unlabelled boxes, the second unlabelled box resolved to "Agree to terms". Unnamed controls are now counted among unnamed controls only.
- **Name lookup was a substring match.** `Add` also matched `Add to cart`, so the position among same-named controls was counted over the wrong set. Exact match is tried first.
- **Page furniture outranked the task's controls.** A "Fork me on GitHub" ribbon held slot `[0]` on a checkbox page; a cheap model clicked it and left. Links to other sites and controls in the header, footer or navigation now lose a point unless they match the task, and ranking applies whenever the list is capped, not only when a task is given.
- **Read mode dropped almost all page text.** Unquoted snapshot lines such as `- paragraph: words` matched no pattern, so paragraphs, list items, table rows and footers vanished and content mode returned headings and links only.
- **`treeitem`, `menuitemcheckbox` and `menuitemradio` could never be acted on.** They were in neither the interactive nor the skipped role set.
- **The server flattened JSON Schemas.** `/extract` turned `{"type": "object", "properties": ...}` into `{"type": str, "properties": str}`, so the schema form the MCP tool documented never worked.
- **The Docker image fetched a browser for a different Camoufox release** than the one the package pins, then downgraded the package underneath it. The Dockerfile now pins the same version.
- **A model served from another machine never had thinking turned off.** Only URLs containing `localhost` or `127.0.0.1` were treated as self-hosted, so a Qwen-style thinking model on a LAN address, a Docker service name or a Tailscale address reasoned through its whole token budget on every step. Private, loopback, link-local, CGNAT and `.local`/`.internal` hosts and bare hostnames now count as self-hosted; `FANTOMA_LLM_SELF_HOSTED=1/0` overrides.
- **Four CAPTCHA tests failed on Python below 3.13**, where logging calls `time.time()` and exhausted a three-item mock.

### Also in 0.10.0 (landed on main after 0.9.0)

#### Fixed

- **Unnamed form controls never reached the model.** The element list required a non-empty accessible name, so a bare `- checkbox` in the ARIA snapshot was discarded. On a page whose only task was "tick the first checkbox", the two elements offered were a GitHub ribbon and a footer link: the task was not hard, it was impossible, on every model. Form-control roles (checkbox, radio, textbox, combobox, searchbox, switch, spinbutton, slider) are now listed when unnamed and labelled from the adjacent text node, rendered as `(in: ...)` because per W3C AccName a neighbour does not contribute to an accessible name. Link, button, menuitem, option and tab are deliberately still excluded when unnamed — an unnamed one of those is usually an icon and admitting them floods the list.
- **Unnamed elements with children were dropped entirely.** The snapshot appends `:` to any element that has children, and the no-name pattern anchored to end-of-string, so `- combobox:` matched nothing. Every unlabelled `<select>` on the web was invisible; on the dropdown page the model was shown the three options but never the control to select on.
- **A field disappeared the moment it was filled.** Once a value is present the snapshot writes `- spinbutton: "42"`, which matched neither pattern. The model typed a value and the box it had just used vanished from the next observation, leaving it unable to confirm the value landed or to correct a mistake.
- **Only the first `[...]` group on a line was kept.** `option "Please select an option" [disabled] [selected]` retained `disabled` and silently discarded `selected`. Selection state is the entire feedback signal for "did my choice take effect", so a successful select was indistinguishable from a no-op and agents re-tried choices they had already made. All attribute groups are now collected, and `[selected]` is rendered.
- **Unnamed elements lost their state.** Attributes on a no-name line were returned as a raw string rather than parsed, so `parsed.get("checked")` was always falsey and an unnamed checkbox rendered without `[checked]` — which is the one fact "tick it if it is not already ticked" depends on.

#### Changed

- **`camoufox` is pinned to an exact version.** It was `>=0.4`, so a routine image rebuild moved 0.4.11 to 0.5.4 with nobody choosing it. The one dependency the anti-detection behaviour rests on should not change silently; bump it deliberately and re-run the protected-site checks when you do.
- **README claims now match measurement.** Reading pages works on a small local model — 30/31 real sites for a 35B local MoE, matching the best cheap API model and beating most. Multi-step interaction does not: the same model completed 1 of 6 login and form flows where a frontier model completed all 6. The distinction is now stated up front rather than implied away.
- **Flow test checkpoints verify the live page.** Three of them asserted that the URL still contained the path the flow *started* on, so they were true before the agent acted: a model that errored on every call and issued no actions at all scored 4 of 6. They now read `[checked]`, `[selected]` and the field value off the live ARIA tree via `keep_session`. A `herokuapp-inputs` flow was added.

## 0.9.0 — 2026-07-25

### Added

- **MCP server** (`fantoma/mcp_server.py`). Any MCP client — Claude Code, Claude Desktop, Cursor, or your own agent — can drive a browser directly. Four tools: `fantoma_run`, `fantoma_login`, `fantoma_extract`, `fantoma_health`. Runs over stdio or streamable HTTP. Install with `pip install "fantoma[mcp]"`, or use the `fantoma-mcp` console script.
- **Backend pool with failover.** Browser backends are single-session, so the MCP server hands out one per call and blocks when they are all busy. List several with `FANTOMA_MCP_BACKENDS` to raise concurrency. A call that meets a restarting backend moves to another one immediately instead of waiting; only the final attempt waits, so a single-backend setup still behaves correctly.
- **Structured task parsing** (`fantoma/task_spec.py`). A task sentence is parsed once into action, target and values, so the navigator matches a named target rather than re-interpreting prose every step. Extraction is deterministic — quoted text is the target in nearly every human-written task, and code finds it more reliably than a small model. An LLM is consulted only when there are no quotes, and its answer is rejected unless it appears verbatim in the task.
- **Outcome verification.** The finished page is checked against the parsed target and a failed check flips `success` to `False`, surfaced as `verified` and `verify_reason`. Verification is fail-open: an unparsed task, or a browser that has already closed, reports ok rather than inventing a failure.
- **`keep_session`** on `/run` (`Agent.run(keep_open=True)`) leaves the browser on the final page so callers can inspect what a run actually did, plus `final_url`, `final_title` and `steps_detail` on the result.
- **Inferred labels for repeated controls.** A product grid names every button "Add to cart", so each is rendered with the item it belongs to as `(in: ...)`, marked as inferred because per W3C AccName a neighbour does not contribute to an accessible name. Relevance scoring reads that context too, since a button called "Add to cart" matches none of the task's keywords.
- **Flow and agentic test harnesses** (`tools/live_flow_test.py`, `tools/live_agentic_test.py`) covering multi-step journeys graded on the browser's end state with partial credit per checkpoint.
- **Live site matrix** (`tools/live_site_matrix.py`). 19 real sites across five difficulty tiers, run through the pool. Each case checks the answer contains something only the correct page would say, so a confident wrong answer counts as a failure. First run: 16/19 in 145s, with protected sites 5/5, JS-heavy 3/3 and docs 4/4.

### Fixed

- **Sessions could not be reused after `stop()`.** `stop()` ran Camoufox's `__exit__` on a worker thread, but Playwright's sync API is thread-bound, so the call failed silently: the driver was never shut down, one browser leaked per session, and the next `start()` raised "Sync API inside the asyncio loop". `__exit__` now runs on the calling thread under a watchdog that kills the driver if it blocks, and is skipped entirely when the driver process is already gone.
- **`/run` after `/login` broke the server.** `/login` and `/start` leave a session open by design, and `/run` then built a second browser on the same thread. Two live sync Playwright instances per thread is not possible. `/run` now releases any existing session first.
- **A crashed browser driver poisoned the worker permanently.** The Playwright Firefox driver dies on some pages (a page JS error with no location kills its bundle), leaving the sync API bound to a dead transport with nothing repairable in-process. Unrecoverable states now return 503 with `retryable: true` and exit, so the supervisor supplies a clean worker.
- **Hung requests are now bounded.** Playwright can hang rather than raise, and a hung worker is worse than a crashed one — a process supervisor sees RUNNING and leaves it alone while the container serves timeouts. Every request runs under a watchdog (75s for `/start`, longer for task endpoints, and always above a client-supplied `timeout`).
- **Extraction could return a previous page's content as a confident answer.** `/start` answers 409 when a session already exists; the MCP extract flow ignored the status and read whatever page was loaded, reporting `success: true`. Observed live: a request for bbc.co.uk/news returned "Example Domain". The session is now cleared before every start, and a start that returns no page state fails loudly instead of guessing.
- **The model's choice of element was discarded.** Resolution looked an element up by role and name and then took `.first`, so all six "Add to cart" buttons on a product grid resolved to the first product no matter which index was chosen. Each control now records its position among identically-named siblings, in DOM order before pruning reorders anything, and resolves with `locator.nth()`.
- **Repeated controls were deleted before the model saw them.** Interactive elements were deduplicated by `(role, name)`, keeping only the first, so five of six "Add to cart" buttons vanished and a specific item could not be chosen at all. Repetition noise is handled by relevance scoring and by capping the list, so the deduplication was redundant as well as destructive.
- **Queued actions reused stale element numbers.** Numbers are captured once per step, so any action after a re-render acted on whatever then sat at that number — two clicks on one index added two different products. A batch now stops when the element set changes; value-only changes do not stop it, so filling a form still works.
- **`changed` reported that nothing had happened after any in-page action.** It was a copy of `url_changed`, so clicking "Add to cart" on a single-page shop reported no change while the button had plainly become "Remove". It now compares the accessibility tree against the previous action's.
- **DONE was accepted without evidence.** A task that asks the agent to act is not finished until something was acted on; the agent announced completion on merely reaching the right page. DONE is now refused until a click, keystroke or selection has succeeded, twice at most so a stuck run still ends.
- **Verification passed runs with unwanted side effects.** Checking only that the target was present passed a run that added the right item and a wrong one. It now fails when more changed than was asked for.
- **22 long-standing test failures.** The landmark and DOM-mode suites had been red since June. The cause was a stale fixture, not a broken feature: the mock page never stubbed `page.evaluate`, so once `extract_aria` gained viewport scroll hints every test raised `TypeError` before reaching any landmark logic. Suite is now 659 passing, zero failing.

### Changed

- README rewritten to lead with the architecture — accessibility tree rather than screenshots, and the token economics that make small local models practical — instead of "undetectable". Two claims that would not survive scrutiny were corrected: accessibility law does not grant automated access a legal right, and no automation is undetectable against session-level behavioural scoring.
- Added `What It's For` and `Responsible Use` sections, and a `Reliability` section documenting crash-only recovery, the request watchdog and failover.
- `/health` deliberately does not start a browser. That is documented now, because a green health check means the HTTP server is up, not that the browser works.

### Notes

The element-resolution defect above is worth calling out: it silently discarded several other correct fixes made alongside it, because every improvement to how the page was presented was thrown away one line before the click. When a fix appears to have no effect, check that the fixed code ran at all — an action cache replaying a plan recorded while a bug was live will happily hide it.

Driver crashes are intermittent rather than tied to particular sites. Pages that repeatedly killed a single backend load fine once there is somewhere to fail over to. Running at least two backends is the difference between a crash being a retry and a crash being a failure.
